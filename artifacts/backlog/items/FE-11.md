## What

Plan section 10. An explicit registry binding every named invariant to the test that defends it and
the mutation that would break it, systematic anti-vacuity over the dangerous collections, and a
harness that breaks the architecture on purpose and asserts the suite objects.

## Why

A test that passes against both the correct implementation and the broken one is not evidence. A
suite made of those is a green build with nothing behind it.

## Notes

The harness caught its own false green on first run. A `node --test` child inheriting
`NODE_TEST_CONTEXT` from a `node --test` parent runs nothing, prints nothing, and exits 0 — so every
mutation reported as uncaught in half a second. The fix is to delete the variable and to require a
test-summary line in the child output before believing any exit code.
