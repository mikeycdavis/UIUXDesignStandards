## What

Plan section 13, phase 13A, acceptance criterion 5. When Gate 0b refuses on version identity,
`validate --json` emits an error envelope carrying the identity state as data, in the shape
`docs/integration-contract.md` §2.2 already fixes for the classifier's `CLASSIFIER_DID_NOT_EXECUTE`.

## Why

Criterion 5 requires that *"the machine-readable identity error survives the workflow boundary
intact"*, and today nothing machine-readable exists to survive it. The refusal is thrown as a
`ValidationError` whose message merely begins with the identity state, so the state name reaches a
consumer only as the first token of a prose string in `validate.err`. An adapter that wanted to
distinguish `EXECUTED_TREE_IS_NOT_THE_RELEASE` from a broken policy would have to parse English.

The second reason is that `envelope.json` is currently written as a **zero-byte file** on refusal.
Empty is not absent, and a consumer cannot tell an identity refusal from a step that never ran — the
same confusion §2.2 exists to prevent on the classifier side.

This is a prerequisite for 13A rather than a parallel improvement: running the external canary before
it means either closing FE-14 on six of seven criteria, or running the canary twice.

## Notes

**The refusal semantics do not change, and that is the whole difficulty.** An identity refusal still
exits 2, still emits no compliance envelope, and still establishes nothing about the project. The
error envelope carries `error` and no `status`, no `uiCompliance`, and no `frameworkCompliance` — so
there is nothing in it a consumer could read as a verdict, which is exactly the classifier's
argument transposed. A record that made a refusal look like a result would be the failure this
framework exists to refuse.

Scope is Gate 0b only, as specified. `validate` reaches exit 2 by other routes — an unreadable
policy, a schema-invalid evidence document, an unknown rule id in ingested evidence — and those
still emit nothing. That asymmetry is deliberate here but is worth revisiting as its own item; it is
not a defect this story introduces, only one it declines to fix.

Not to be worked alongside the `SKIP_PATHS` fixture-scan finding: both amend `test/falsifiers.mjs`
and `test/invariants.mjs`, so they conflict on a shared surface despite touching different scripts.
