## What

Plan section 13, phase 13B. An external repository consuming the reusable workflow at an immutable
released tag, reaching `identity: MATCH` and a real verdict — then both negative controls repeated
against that released workflow rather than against a branch.

## Why

13A can prove the distribution boundary works, but only by proving a refusal. Until a release exists
that contains the workflow and the guard, "successfully consumed as a released standards dependency"
is a claim with no evidence behind it, and the framework should not make it.

## Notes

Blocked on `v2.0.0`, not on effort. The published `v1.0.0` predates both the reusable workflow and
the version-identity guard, and the development line that has them correctly refuses to be called
`1.0.0` — which is the guard working rather than a defect.

The increment is MAJOR because the guard removes a previously accepted execution path: an existing
v1.0.0 consumer can get exit 2 without changing its project. A bug fix can still be breaking. See
ADR 0017.

Resolving this by weakening the guard, or by manufacturing a tag to test against, is explicitly
rejected — both are the failure modes this framework exists to refuse.
